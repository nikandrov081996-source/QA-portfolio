# **Тест-план веб-приложения CodeVoyager**

## 1. **Общая информация**

   - **Объект тестирования**: Веб-приложение по автодокументированию кода CodeVoyager
   - **Тип документа**: Тест-план
   - **Статус документа**: В процессе редактирования
   - **Версия документа**: 1.1

## 2. **Цели тестирования**
  Целью тестирования данного веб-приложения является оценка его качества, путём проверок:
  - корректности реализации основной функциональности проекта;
  - обработки исключительных ситуаций и работы с невалидными входными данными;
  - разграничение доступа к пользовательскому аккаунту и его данным в частности;
  - удобства использования пользовательского интерфейса.

  В рамках тестирования **планируется**:
  - проверить соответствие фактического поведения приложения ожидаемым результатам;
  - проверить обработку некорректных входных данных и ошибок при выполнении основных операций;
  - проверить разграничение доступа к пользовательским проектам и защиту от несанкционированного доступа;
  - проверить корректность сохранения, просмотра истории версий и восстановления файлов;
  - оценить понятность интерфейса и возможность выполнения основных пользовательских сценариев без затруднений.

## 3. **Область тестирования**
В ходе проведения тестирования веб-приложения, в область тестирования будут входить следующие компоненты:
### 1. Регистрация и авторизация
- Регистрация пользователя;
- Вход пользователя в уже ранее созданный аккаунт;
- Восстановление пароля пользователя через вкладку "Забыли пароль?" (Доступно только с включённой 2FA);
- Смена пароля пользователя;
- Подключение двухфакторной аутентификации.
  
### 2. **Управление проектами**
- Добавление нового проекта (как через ZIP-файл, так и при помощи ссылки на публичный репозиторий GitHub);
- Закрепление проекта в меню проектов пользователя;
- Изменение названия проекта;
- Удаление проекта;
- Экспорт проекта в ZIP.

### 3. **Анализ кода и документация**
- Проверка анализа проекта;
- Проверка дерева файлов в проекте;
- Проверка документации файла в проекте;
- Генерация документации файла в проекте (как полностью, так и точечно).

### 4. **Чат с ИИ и индексация кода**
- Проверка отправки вопросов по коду;
- Истории чата, очистка истории;
- Состояния индексации проекта и обновление индекса.

### 5. **Работа с файлами**
- Редактирование и сохранение файлов;
- Просмотр истории изменений;
- Отмена правок в файле;
- Просмотр истории версий файла и восстановление предыдущих версий.

### 6. **Генерация комментариев с помощью ИИ**
- Генерация комментариев;
- Предварительный просмотр и применение изменений.

### 7. **Безопасность и обработка ошибок**
- Разграничения доступа к проектам разных пользователей;
- Обработка некорректных запросов.

### 8. Пользовательский интерфейс
- Проверка отображения основных элементов и возможности выполнять ключевые пользовательские сценарии.

## 4. **Подход к тестированию**
В рамках тестирования веб-приложения CodeVoyager, будут использоваться следующие виды тестирования:
- 4.1. Функциональное тестирование (проверка основных возможностей и пользовательских сценариев в веб-приложении и соответствие его работы ожидаемым результатам);
- 4.2. Нефункциональное тестирование (проверка пользовательского интерфейса, удобства взаимодействия с продуктом, безопасности);
- 4.3. Дымовое тестирование (краткая проверка работоспособности приложения и его основных функций перед проведением более подробного тестирования);
- 4.4. Негативное тестирование (проверка приложения на обработку невалидных данных, данных с неверным форматом, различных недопустимых действий).

В рамках тестирования веб-приложения CodeVoyager, будут использоваться следующие техники тест-дизайна:
- Тестирование граничных значений (проверка поведения приложения на границах допустимых диапазонов входных данных и значениях, расположенных рядом с этими границами);
- Попарное тестирование (планируется использовать для проверки совместимости различных комбинаций настроек генерации комментариев с помощью ИИ/настроек помощника, просмотра кода, внешнего вида и языка).

**Результаты проверок** планируется фиксировать в **тест-кейсах** и **отчётах о дефектах**. Обнаруженные отклонения от ожидаемого поведения будут **документироваться** в баг-репортах с указанием шагов воспроизведения, фактического и ожидаемого результатов.

## 5. **Тестовое окружение**
Тестирование веб-приложения CodeVoyager будет производиться в веб-браузере на уже развертываемом сервере.
### 5.1. Клиентское окружение
- Операционная система: Windows 10 Домашняя v.22H2 (x64)
- Браузер: Google Chrome
- Версия: 156.0.8078.35 (официальная сборка) (64 бит)

### 5.2. Окружение приложения
- Версия приложения: CodeVoyager 1.3.
- Способ размещения: веб-приложение развёрнуто на сервере.
- Адрес тестового экземпляра: https://codevoyager.click/

## 6. **Риски и ограничения**
При тестировании веб-приложения CodeVoyager необходимо учитывать следующие потенциальные риски и ограничения:
1. Работа функций генерации комментариев и взаимодействия с ИИ зависит от доступности и корректной работы внешнего ИИ-провайдера. Сбои внешнего сервиса могут препятствовать выполнению соответствующих проверок;
2. Результаты генерации комментариев и ответов в чате могут различаться при повторных запросах. При проверке необходимо оценивать соответствие результата заданным требованиям, а не требовать полного совпадения текстов;
3. Нестабильное интернет-соединение может повлиять на выполнение тестовых сценариев. При возникновении подобных ситуаций необходимо учитывать возможность внешней причины сбоя.

## 7. **Критерии начала и завершения тестирования**
### 7.1. Критерии начала тестирования
К проведению основных проверок планируется приступить при выполнении следующих условий:
- тестируемое приложение доступно по публичной ссылке;
- подготовлено клиентское окружение для тестирования;
- определены основные пользовательские сценарии;
- подготовлены необходимые тестовые данные (аккаунты).
### 7.2. Критерии завершения тестирования
Тестирование считается завершённым после выполнения запланированного объёма проверок и документирования их результатов.
Критерии завершения:
- выполнены запланированные тест-кейсы либо зафиксированы причины их невыполнения;
- фактические результаты проверок задокументированы;
- обнаруженные дефекты оформлены в виде баг-репортов;
- результаты проверки основных функциональных возможностей зафиксированы;
- известные ограничения, невыполненные проверки и обнаруженные дефекты отражены в итоговых результатах тестирования.

Завершение тестирования не гарантирует полного отсутствия дефектов в приложении, а отражает выполнение согласованного объёма проверок.

## 8. **Результаты тестирования и тестовая документация**
В ходе тестирования веб-приложения CodeVoyager планируется вести тестовую документацию, необходимую для описания проверок, фиксации их результатов и регистрации обнаруженных дефектов.
- 8.1. Чек-листы
Чек-листы будут использоваться для фиксации основных проверок функциональности приложения. Они позволят отслеживать, какие области приложения были проверены, а какие требуют дополнительного внимания.
- 8.2. Тест-кейсы
Для проверки отдельных пользовательских сценариев будут составлены тест-кейсы, содержащие предусловия, тестовые данные, последовательность шагов и ожидаемый результат.
Фактический результат выполнения тест-кейса будет фиксироваться по итогам проверки. Для каждого выполненного тест-кейса будет указываться соответствующий статус.
- 8.3. Баг-репорты
Обнаруженные дефекты будут документироваться с помощью баг-репортов. Каждый баг-репорт должен содержать краткое описание проблемы, условия её возникновения, шаги воспроизведения, ожидаемый и фактический результаты, а также дополнительную информацию, необходимую для анализа дефекта.
При необходимости к баг-репортам будут прикладываться скриншоты и другие материалы, подтверждающие обнаруженную проблему.
- 8.4. Итоговый отчёт о тестировании
По завершении запланированных проверок будет подготовлен итоговый отчёт, содержащий информацию о выполненном объёме тестирования, результатах проверок, обнаруженных дефектах и ограничениях тестирования.
Итоговый отчёт позволит оценить текущее состояние проверенных функций приложения и определить области, требующие дальнейшего тестирования.

## 9. **Тестовые данные**
Для проведения тестирования веб-приложения CodeVoyager планируется подготовить набор тестовых данных, позволяющий проверять основные пользовательские сценарии, обработку некорректных входных данных и работу с пользовательскими проектами.
### 9.1. Данные пользователей
Для проверки регистрации, авторизации и управления учётной записью планируется использовать тестовые учётные записи:
- данные для регистрации нового пользователя;
- данные существующего пользователя для проверки авторизации;
- некорректные и граничные значения полей регистрации и авторизации;
- данные для проверки смены пароля.

Учётные записи и пароли будут использоваться исключительно для тестирования и не будут публиковаться в открытом репозитории.
### 9.2. Данные проектов
Для проверки управления проектами планируется использовать тестовые проекты, содержащие файлы исходного кода.
Будут подготовлены данные для проверки:
- создания проекта из ZIP-архива;
- добавления проекта из публичного репозитория GitHub;
- переименования и удаления проекта;
- закрепления проекта;
- экспорта проекта в ZIP-архив.

Для негативных проверок будут использоваться неподходящие или некорректно подготовленные входные данные.
### 9.3. Файлы исходного кода
Для проверки анализа кода, генерации документации, редактирования и восстановления версий будут использоваться файлы с заранее известным содержимым.
В набор тестовых данных планируется включить:
- файл с корректным исходным кодом;
- файл с синтаксической ошибкой;
- файл, содержащий несколько функций или классов для проверки анализа и генерации документации;
- файл, который можно изменять и сохранять несколько раз для проверки истории версий и восстановления предыдущего состояния.
  
### 9.4. Данные для негативных и граничных проверок
Для проверки обработки некорректных данных планируется использовать:
- пустые значения в полях, где ожидается ввод;
- значения, содержащие только пробелы;
- некорректные форматы данных;
- неподдерживаемые или повреждённые файлы;

Конкретные значения будут определяться в соответствующих чек-листах и тест-кейсах с учётом фактических ограничений приложения.
